🎣 Хук useHybridSearch
| Гибридный поиск: локальная фильтрация + глобальный поиск через бэкенд с умным переключением.

📋 Сигнатура

useHybridSearch<T>(
localData: T[],
localFilterFn: (items: T[], searchTerm: string) => T[],
globalSearchFn: (searchTerm: string, signal?: AbortSignal) => Promise<T[]>,
debounceDelay?: number, // по умолчанию 300
globalPrefix?: string, // по умолчанию '@'
globalMinLength?: number // ✨ NEW: по умолчанию 3
): UseHybridSearchReturn<T> // ✨ NEW: экспортированный тип

🔧 Параметры

# localData: T[]

Исходный массив данных для локальной фильтрации.
Пример: кешированные чаты из RTK Query.

# localFilterFn: (items: T[], searchTerm: string) => T[]

Функция фильтрации локальных данных. Должна возвращать отфильтрованный массив.
Пример: filterChatsLocal(chats, 'айрат').

# globalSearchFn: (searchTerm: string, signal?: AbortSignal) => Promise<T[]>

Асинхронная функция запроса к бэкенду. Поддерживает AbortSignal для отмены запросов.
Пример: обёртка над useLazyGetChatsQuery().unwrap().

# debounceDelay?: number (по умолчанию 300)

Задержка в миллисекундах перед выполнением поиска. Снижает нагрузку при быстром вводе.

# globalPrefix?: string (по умолчанию '@')

Префикс, который активирует глобальный поиск.
Пример: ввод @айрат → поиск на бэке, ввод айрат → локальная фильтрация.

# globalMinLength?: number (по умолчанию 3, ✨ новый параметр)

Минимальная длина запроса для вызова API. Если после удаления префикса длина меньше — запрос к бэкенду не отправляется.
Зачем: экономия трафика, защита от лишних запросов при коротких/бессмысленных вводах (@а, @).

📦 Возвращаемое значение
Хук возвращает объект с тремя группами данных:

🔹 Состояние поиска

- searchTerm: string — текущее значение поля поиска (сырой ввод пользователя).
- isGlobal: boolean — активен ли глобальный режим (определяется по префиксу).
- isLoading: boolean — идёт ли загрузка глобальных результатов.
- error: Error | null — ошибка глобального запроса (если была).

🔹 Результаты (три массива!)

- globalResults: T[] — данные, полученные от бэкенд-API.
  Используй, когда нужно показать только результаты полного поиска.

- localResults: T[] — локально отфильтрованные данные.
  Используй для мгновенного отклика, offline-режима или показа "последних" элементов.

- results: T[] — ✨ "умный" объединённый массив:
- isGlobal ? globalResults : localResults;
  Используй для простого рендера без логики переключения — готово к map().

🔹 Обработчики

- handleSearchChange: (value: string) => void — основной обработчик ввода (передавай в onChange поля поиска).

- handleClear: () => void — полная очистка поиска и результатов.

🔹 Продвинутые методы (опционально)

- setGlobalResults: Dispatch<T[]> — прямое управление глобальными результатами (редко нужно).
- setLocalResults: Dispatch<T[]> — прямое управление локальными результатами (для кастомной логики).

🎯 Примеры использования
✅ Вариант 1: Простой рендер (через results)

const { results, handleSearchChange, handleClear, searchTerm } = useHybridSearch<Chat>(
localChats,
filterChatsLocal,
fetchGlobalChats,
300,
'@',
3 // ← globalMinLength: не искать, если < 3 символов после @
);

return (
<>
<Search value={searchTerm} onChange={handleSearchChange} onClear={handleClear} />

    {results.length === 0 ? (
      <EmptyChats />
    ) : (
      <List>
        {results.map(chat => (
          <ChatItem key={chat.id} chat={chat} />
        ))}
      </List>
    )}

</>
);

✅ Вариант 2: Гибкий рендер (раздельные массивы)

const {
searchTerm,
globalResults, // 🔹 Массив 1: от API
localResults, // 🔹 Массив 2: локальный
results, // 🔹 "Умный" массив (auto-select)
isGlobal,
isLoading,
handleSearchChange,
handleClear
} = useHybridSearch(chats, filterChats, api.searchChats);

return (
<>
<Search value={searchTerm} onChange={handleSearchChange} onClear={handleClear} />

    {/* Показываем локальные результаты всегда (например, "последние чаты") */}
    <Section title="Последние чаты">
      {localResults.slice(0, 5).map(chat => (
        <ChatItem key={chat.id} chat={chat} />
      ))}
    </Section>

    {/* Если глобальный поиск активен — показываем API-результаты отдельно */}
    {isGlobal && (
      <Section title="Найдено в базе">
        {isLoading ? (
          <Spinner />
        ) : globalResults.length > 0 ? (
          globalResults.map(chat => (
            <ChatItem key={chat.id} chat={chat} highlight />
          ))
        ) : (
          <Empty text="Ничего не найдено" />
        )}
      </Section>
    )}

</>
);

✅ Вариант 3: Кастомное объединение (merge без дублей)

const { globalResults, localResults } = useHybridSearch(...);

// Объединяем: глобальные + уникальные локальные (без дублей по ID)
const mergedResults = useMemo(() => {
const globalIds = new Set(globalResults.map(item => item.id));
const uniqueLocal = localResults.filter(item => !globalIds.has(item.id));
return [...globalResults, ...uniqueLocal];
}, [globalResults, localResults]);

return (
<List>
{mergedResults.map(item => (
<Item key={item.id} data={item} />
))}
</List>
);

🔍 Визуальная схема работы

useHybridSearch(...)
│
├── 📊 Состояние
│ ├── searchTerm: string ← текущий ввод
│ ├── isGlobal: boolean ← режим: локальный/глобальный
│ ├── isLoading: boolean ← загрузка API
│ └── error: Error | null ← ошибка запроса
│
├── 📦 Результаты (три массива!)
│ ├── globalResults: T[] ← от API (только при @ + длина ≥ globalMinLength)
│ ├── localResults: T[] ← локальная фильтрация (мгновенно)
│ └── results: T[] ← computed: isGlobal ? global : local ✨
│
├── ⚙️ Обработчики
│ ├── handleSearchChange: (value: string) => void
│ └── handleClear: () => void
│
└── 🎛 Продвинутые (опционально)
├── setGlobalResults: Dispatch<T[]>
└── setLocalResults: Dispatch<T[]>

💡 Практические советы

🎯 Когда использовать results
✅ Тебе нужно просто отрендерить список
✅ Логика "глобальный приоритет" подходит
✅ Не нужна сложная UI-логика переключения

🎯 Когда использовать globalResults / localResults раздельно
✅ Хочешь показать оба списка одновременно (например, "рекомендации" + "найденное")
✅ Нужна разная визуализация для глобальных/локальных элементов
✅ Планируешь кастомную логику объединения (merge, сортировка, приоритеты)

🎯 Как работает globalMinLength

- Ввод: "@а" → длина после @ = 1 < 3 → ❌ запрос к API НЕ уходит
- Ввод: "@ай" → длина после @ = 2 < 3 → ❌ запрос к API НЕ уходит
- Ввод: "@айр" → длина после @ = 3 ≥ 3 → ✅ запрос уходит после debounce

Зачем: защита от спама короткими запросами, экономия трафика, снижение нагрузки на бэкенд.

⚠️ Важные заметки
🔹 AbortController: хук автоматически отменяет предыдущие запросы при новом вводе — утечек памяти и race conditions не будет.
🔹 Дебаунс: и локальный, и глобальный поиск используют debounce — не забудь, что результаты появляются с задержкой debounceDelay.
🔹 Инициализация: при пустом searchTerm хук автоматически заполняет localResults всеми localData — список не будет пустым при загрузке.
🔹 Префикс: globalPrefix проверяется через trim().startsWith() — пробелы до/после @ не сломают логику.
🔹 Типизация: дженерик <T> распространяется на все массивы — убедись, что localFilterFn и globalSearchFn работают с одним типом.

🧪 Пример интеграции с RTK Query

// 1. Lazy-триггер для глобального поиска
const [triggerSearch] = useLazyGetChatsQuery();

const fetchGlobalChats = useCallback(
async (term: string, signal?: AbortSignal): Promise<Chat[]> => {
// RTK Query сам управляет отменой, но signal можно передать в baseQuery
const result = await triggerSearch({
search: term,
pageSize: 50,
ordering: '-last_activity_at'
}).unwrap();
return result?.results ?? [];
},
[triggerSearch]
);

// 2. Использование хука
const { results, handleSearchChange } = useHybridSearch<Chat>(
localChats, // из кеша: cacheResponse?.results ?? []
filterChatsLocal, // оптимизированная фильтрация
fetchGlobalChats, // запрос к API
300, // debounce
'@', // префикс
3 // ✨ globalMinLength
);
